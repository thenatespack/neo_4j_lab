📖 Cypher Quick Reference
MATCH

Finds a pattern of nodes/relationships that already exist in the graph. The core "read" clause — almost every query starts with one.

MATCH (n:Label) RETURN n
CREATE

Always creates a brand-new node or relationship, even if an identical one already exists. Fine for a one-time script, risky for anything you might re-run.

CREATE (n:Label {name: "x"})
MERGE

Matches a pattern if it exists, otherwise creates it. Idempotent — re-running a script full of MERGEs won't produce duplicates, which is why build_graph() should use it.

MERGE (n:Label {name: $name})
Relationships

Written between two node patterns with an arrow showing direction. A type after *min..max matches a variable-length chain of hops instead of exactly one.

(a)-[:TYPE]->(b) (a)-[:TYPE*1..5]->(b) // 1 to 5 hops, any path
WHERE

Filters rows already matched, using any boolean condition on their properties.

WHERE n.property = $value
RETURN

Chooses what a query outputs — whole nodes, individual properties, or computed expressions. Use AS to name a column.

RETURN n.name AS name
WITH

Pipes values from one part of a query into the next, like a checkpoint. Required whenever you aggregate something and then need to filter or sort on that aggregate.

WITH n, count(m) AS total WHERE total > 1
Aggregating

count(), count(DISTINCT x), collect(), etc. summarize grouped rows. Anything in RETURN/WITH that isn't wrapped in one of these is implicitly what the rows get grouped by.

RETURN n.name, count(m) AS total
ORDER BY / LIMIT

Sorts the result rows and, optionally, caps how many come back.

ORDER BY total DESC LIMIT 5
Parameters

A $name placeholder in the query text, filled in via a keyword argument to .run(). Always use these instead of f-string-ing values into Cypher — it avoids injection and lets Neo4j reuse the query plan.

session.run("... WHERE n.name = $name", name=x)
